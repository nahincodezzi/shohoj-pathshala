# ADR 0001: Monorepo Architecture with pnpm Workspaces

## প্রেক্ষাপট (Context)
সহজ পাঠশালা একটি সম্পূর্ণ মাল্টি-টেন্যান্ট প্ল্যাটফর্ম যেখানে ফ্রন্টএন্ড ওয়েব অ্যাপ, ব্যাকএন্ড এপিআই সার্ভিস এবং একাধিক শেয়ার্ড কনফিগারেশন প্যাকেজ (ডিজাইন টোকেন, কন্ট্রাক্টস, কনফিগ রেজিস্ট্রি, অনুবাদ) রয়েছে। আলাদা আলাদা রিপোজিটরিতে রাখলে প্যাকেজ ভার্সনিং, টাইপ শেয়ারিং ও সমন্বয় অত্যন্ত জটিল এবং ভঙ্গুর হয়ে পড়ে।

## সিদ্ধান্ত (Decision)
আমরা **Monorepo (pnpm workspaces)** আর্কিটেকচার গ্রহণ করার সিদ্ধান্ত নিয়েছি:
- `apps/web`: React + Vite + TypeScript ফ্রন্টএন্ড।
- `apps/api`: Flask + SQLAlchemy + Pydantic ব্যাকএন্ড।
- `packages/design-tokens`: সেন্ট্রাল ডিজাইন টোকেনস।
- `packages/config`: মডিউল, পারমিশন ও প্ল্যান রেজিস্ট্রি।
- `packages/contracts`: জেনারেটেড টাইপস্ক্রিপ্ট টাইপস।
- `packages/i18n`: বহুভাষিক ডিকশনারি।

## বিকল্প বিবেচনা (Alternatives Considered)
1. **Multi-repo:** প্রতিটি প্যাকেজের জন্য আলাদা গিট রিপোজিটরি। (বাতিল: টাইপ সিঙ্ক করতে ভার্সন রিলিজের ওভারহেড বেশি)।
2. **Lerna / Nx:** অতিরিক্ত জটিল বিল্ড কনফিগারেশন প্রয়োজন। (বাতিল: pnpm workspace নিজেই যথেষ্ট দ্রুত ও হালকা)।

## ফলাফল ও প্রভাব (Consequences)
- **ইতিবাচক:** একই কমিটে ফ্রন্টএন্ড, ব্যাকএন্ড ও ডিজাইনের পরিবর্তন নিশ্চিত করা যায়। ডিপেনডেন্সি ডুপ্লিকেশন দূর হয়।
- **নেতিবাচক:** মোনোরিপোর জন্য সেন্ট্রাল সিআই/সিডি ওয়ার্কফ্লো সঠিকভাবে কনফিগার করতে হয়।
