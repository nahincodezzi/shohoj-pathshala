# ADR 0010: Unified Print Architecture with Dynamic Letterhead

## প্রেক্ষাপট (Context)
স্কুল ব্যবস্থাপনায় মুদ্রণ (Printing) অন্যতম গুরুত্বপূর্ণ ফিচার: মানি রিসিট, পরীক্ষার মার্কশিট, ট্যাবুলেশন শিট, স্টুডেন্ট আইডি কার্ড, অ্যাডমিট কার্ড ও নোটিশ প্রিন্ট। প্রতিটি ডকুমেন্টে যদি আলাদা আলাদাভাবে লেটারহেড, প্রতিষ্ঠানের নাম, ঠিকানা ও সিল ডিজাইন করা হয়, তবে কোনো স্কুলের ঠিকানা বা লোগো আপডেট হলে সব প্রিন্ট টেমপ্লেট অসামঞ্জস্যপূর্ণ হয়ে পড়ে।

## সিদ্ধান্ত (Decision)
আমরা **Unified Print Architecture** নীতি গ্রহণ করেছি:
- একক সেন্ট্রাল লেটারহেড কম্পোনেন্ট: `apps/web/src/print/Letterhead.tsx`
- একক প্রিন্ট শেল: `apps/web/src/print/PrintLayout.tsx`
- প্রতিটি প্রিন্ট টেমপ্লেট (`ReceiptPrint`, `AdmitCardPrint`, `MarksheetPrint`) এই সেন্ট্রাল লেটারহেডকে প্যারেন্ট হিসেবে গ্রহণ করে।
- সিএসএস প্রিন্ট টোকেন (`packages/design-tokens/src/print.css`) সবসময় অফিশিয়াল A4/Legal সাইজ এবং উচ্চ কন্ট্রাস্টের সাদা-কালো রেন্ডারিং নিশ্চিত করে।

## বিকল্প বিবেচনা (Alternatives Considered)
1. **Server-Side PDF Generation (wkhtmltopdf / WeasyPrint):** ফন্ট রেন্ডারিং বাংলা যুক্তাক্ষরে ভেঙে যায় এবং সার্ভারের অতিরিক্ত মেমোরি নষ্ট হয়। (বাতিল: ব্রাউজারের নেটিভ `window.print()` ইঞ্জিন আধুনিক CSS সাপোর্ট সহ নিখুঁত ভেক্টর প্রিন্ট দেয়)।
2. **Individual Custom Headers:** প্রতি প্রিন্ট ফাইলে আলাদা হেডার লেখা। (বাতিল: রক্ষণাবেক্ষণ অসম্ভব)।

## ফলাফল ও প্রভাব (Consequences)
- **ইতিবাচক:** স্কুলের সিল, মনোগ্রাম বা ঠিকানায় কোনো পরিবর্তন হলে এক ক্লিকে সমস্ত প্রিন্ট ডকুমেন্টে স্বয়ংক্রিয়ভাবে কার্যকর হয়ে যায়।
- **নেতিবাচক:** ক্লায়েন্ট ব্রাউজারের প্রিন্ট ডায়ালগ দিয়ে পিডিএফ সেভ করতে হয়।
