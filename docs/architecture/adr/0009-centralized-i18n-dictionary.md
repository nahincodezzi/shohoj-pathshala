# ADR 0009: Centralized Multi-Language Dictionary (i18n)

## প্রেক্ষাপট (Context)
সহজ পাঠশালা মূলত বাংলা মাধ্যম স্কুলের জন্য তৈরি, তবে ওনার প্যানেল ও উন্নত রিপোর্টগুলোতে দ্বিভাষিক (বাংলা + ইংরেজি) সমর্থন আবশ্যক। কোডের ভেতরে সরাসরি বাংলা টেক্সট ছড়িয়ে থাকলে বানান ভুল ঠিক করা বা নতুন ভাষা যোগ করা দুরূহ হয়ে পড়ে।

## সিদ্ধান্ত (Decision)
আমরা **Centralized JSON Dictionary** আর্কিটেকচার চূড়ান্ত করেছি:
- সমস্ত টেক্সট `packages/i18n/` ডিরেক্টরিতে থাকবে:
  - `bn/`: `common.json`, `public.json`, `admin.json`, `owner.json`, `validation.json`
  - `en/`: একই সমমানের ইংরেজি ফাইল।
- JSX ফাইলে শুধু কী ব্যবহৃত হবে: `t('public.notices.title')`।
- সিআই বিল্ড স্টেপে স্বয়ংক্রিয় স্ক্রিপ্ট দিয়ে নিশ্চিত করা হবে:
  1. বাংলা ও ইংরেজি ফাইলে কোনো কী মিসিং আছে কিনা।
  2. কোড ফাইলের ভেতরে সরাসরি হার্ডকোডেড বাংলা স্ট্রিং লেখা হয়েছে কিনা।

## বিকল্প বিবেচনা (Alternatives Considered)
1. **Hardcoded Bangla in JSX:** শুরুতে দ্রুত হলেও পরবর্তীতে অনুবাদ ও পরিবর্তন অসম্ভব। (বাতিল)।
2. **Database-stored UI translations:** সাধারণ UI বাটনের লেখার জন্য প্রতিবার ডেটাবেস হিট করা পারফরম্যান্সের জন্য ক্ষতিকর। (বাতিল: শুধু স্কুলের নিজস্ব তথ্য যেমন নাম বা বাণী ডেটাবেসে থাকবে; UI শব্দকোষ JSON-এ থাকবে)।

## ফলাফল ও প্রভাব (Consequences)
- **ইতিবাচক:** কোনো টেক্সট বা ভুল বানান ঠিক করতে কোডে হাত দেওয়া লাগে না; যেকোনো অনুবাদক ১টি JSON ফাইল খুলে পরিবর্তন করতে পারেন।
- **নেতিবাচক:** ডেভলপমেন্টের সময় নতুন লেখা যোগ করার সময় ডিকশনারি কী ডিক্লেয়ার করার অভ্যাসে অভ্যস্ত হতে হবে।
