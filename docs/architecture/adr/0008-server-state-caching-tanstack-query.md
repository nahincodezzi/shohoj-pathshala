# ADR 0008: Server-State Caching and Stale-While-Revalidate with TanStack Query

## প্রেক্ষাপট (Context)
স্কুল ম্যানেজমেন্ট অ্যাপ্লিকেশনে প্রচুর ডেটা ফেচিং থাকে (শিক্ষার্থী তালিকা, রুটিন, নোটিশ, রেজাল্ট)। যদি প্রতি পেজ নেভিগেশনে পুনরায় পুরো সার্ভার কল হয়, তবে ধীরগতির ইন্টারনেটে অ্যাপ স্লো মনে হয়। আবার Redux বা ক্লায়েন্ট গ্লোবাল স্টেটে সার্ভার ডেটা ম্যানুয়ালি সিঙ্ক রাখা অত্যন্ত জটিল।

## সিদ্ধান্ত (Decision)
আমরা **TanStack Query (React Query)** দিয়ে সার্ভার স্টেট ক্যাশিং ও সিঙ্ক চূড়ান্ত করেছি:
- সার্ভার ডেটা (Students, Notices, Results) কোনো গ্লোবাল ক্লায়েন্ট স্টেটে (Zustand) রাখা হবে না; পুরোটাই TanStack Query ক্যাশে থাকবে।
- কুয়েরি কীতে সবসময় টেন্যান্ট স্লাগ প্রিফিক্স থাকবে: `['tenant', slug, 'feature', ...params]`।
- মিউটেশনের পর টার্গেটেড ইনভ্যালিডেশন:
  ```typescript
  queryClient.invalidateQueries({ queryKey: ['tenant', slug, 'notices'] });
  ```
- ক্লায়েন্ট স্টেট (ডার্ক মোড টগল, ড্রয়ার ওপেন/ক্লোজ, মডাল স্টেট) শুধুমাত্র হালকা **Zustand** স্টোরে থাকবে।

## বিকল্প বিবেচনা (Alternatives Considered)
1. **Redux Toolkit:** বয়লারপ্লেট কোড অনেক বেশি এবং ক্যাশ ইনভ্যালিডেশন ম্যানুয়াল। (বাতিল)।
2. **SWR:** TanStack Query-এর মতো উন্নত মিউটেশন ও ক্যাশ অপ্টিমাইজেশন ফিচার সীমিত। (বাতিল)।

## ফলাফল ও প্রভাব (Consequences)
- **ইতিবাচক:** তাৎক্ষণিক পেজ নেভিগেশন (Optimistic Updates সহ), স্বয়ংক্রিয় ব্যাকগ্রাউন্ড রিফেচিং, এবং শূন্য ডেটা ডুপ্লিকেশন।
- **নেতিবাচক:** কুয়েরি কী命名-এ শৃঙ্খলা বজায় রাখা জরুরি।
